# Unplugin

> 디지털에 쓰는 시간을 AI 에이전트에게 위임하고, 그 시간을 오프라인의 진짜 경험으로 되돌려주는 컨시어지 서비스.

## 무엇이 다른가

Meta Muze, OpenAI Dots 같은 AI 비서는 "일을 대신 해주는 것" 자체가 목적입니다.
Unplugin의 목적은 그 다음입니다 — **확보된 시간을 오프라인에서 더 가치 있게 쓰도록 발굴하고 개인화 추천하는 것.**

- 병원 문진처럼, 사용자가 지금 디지털로 무엇을 하고 있는지 Survey
- 그중 하나씩 골라 AI 에이전트에게 위임
- 확보된 시간만큼 오감을 자극하는 오프라인 경험을 추천

## 북극성 KPI

**온라인 시간 → 오프라인 시간 전환량 (Reclaimed Hours)**

모든 부문의 의사결정은 이 지표를 높이는 방향으로 정렬됩니다. 상세 설계는 [`ops/kpi.md`](ops/kpi.md).

## 회사 구조 (1인 대표 + AI 에이전트 부문)

이 저장소는 실제로 운영되는 회사입니다. 대표(사람) 1명이 지시하고, AI 에이전트 부문들이 유기적 워크플로우로 업무를 처리합니다.

```
unplugin/
├── CLAUDE.md              # 회사 헌장 (미션·KPI·운영 원칙만. 실무 규칙은 각 부문에)
├── .claude/agents/        # 실행 가능한 부문 에이전트 (Claude Code 서브에이전트)
├── departments/           # 부문별 CLAUDE.md — 각 부문이 독립적으로 바이브코딩/진화
│   ├── product/           #   상품기획: 오프라인 경험 발굴·개인화 추천·문진 설계
│   ├── marketing/         #   마케팅: 사용자 스토리 기반 콘텐츠
│   ├── it/                #   IT: 에이전트·툴·서비스 개발 (AI 브라우저 세션 연동 포함)
│   └── cs/                #   CS: 고객 응대·문진 진행·피드백 수집
├── workflows/             # 부문 간 업무 흐름 정의 (고객 요청, 대표 지시, 콘텐츠 파이프라인)
├── flows/                 # 실행된 모든 업무 Flow의 기록 — 대표가 한눈에 보는 Unified View
├── ops/                   # KPI 설계, 큐 기반 요금제, 온보딩 문진
├── tests/                 # E2E 고객 시나리오 테스트케이스 (TDD — 개발은 TC를 PASS 시키는 방향으로)
└── docs/                  # 회사 홈페이지 (GitHub Pages)
```

## 운영 코어 v0 (`core/`)

실제로 돌아가는 서비스 코어 — stdlib-only Python, 맥북에서 바로 실행:

```bash
python3 -m core onboard tests/fixtures/onboard-demo.json  # 온보딩 + 전용 주소 발급 + 환영 메일
python3 -m core mail-poll    # data/inbox/ 수신 처리 (포워딩 위임·규칙·격리)
python3 -m core queue-run    # 티어 슬롯 큐 + 결제 승인 게이트
python3 -m core dashboard    # 대표용 Unified View (data/dashboard.html)
python3 tests/e2e_runner.py  # 전 구간 통합 검증
```

**고객은 메일함으로 전체 흐름을 본다**: 모든 Flow 전환(접수→진행→확인→완료)마다 같은
스레드로 상태 메일 + 타임라인이 발송된다(`data/outbox/`에서 확인).

## 미루던 골칫거리 먼저 — 스트레스 케이스 엔진

환불·분쟁·해지·보증금처럼 **한번 시작하면 오래 걸리고 감정이 소모되는 일**은
일반 위임과 다르게 처리됩니다 — 멘탈 케어가 목적이므로 대기열 최우선입니다.

- **10개 유형 플레이북** (`core/stress.py`): 이메일 협상형 / 포털 실행형 / 하이브리드
- **이메일 협상** (`core/negotiation.py`): 과거 히스토리를 포함해 상대방과 멀티라운드로
  주고받으며 결과를 냄 — 정중한 요구 → 법적 근거 재제시 → 최후 통첩 → 에스컬레이션 제안
- **포털 실행** (`core/egolite.py`): egolite AI 브라우저 세션에 인텐트를 넘겨 해당
  시스템의 환불 절차를 완료하고 접수번호·증빙을 회수
- **사람 개입** (`core/hitl.py`): 봇을 차단하는 사이트(앱스토어·정부24 등)는 직원이
  그대로 따라 할 클릭 단위 가이드를 발행하고, 완료 보고 즉시 자동 재개
- **완료 추적** (`core/tracking.py`): 요청 접수로 끝나지 않는다 — **실제 입금이 확인될
  때까지** Flow는 완료되지 않고, 기한 초과 시 상대방에게 확인을 독촉
- **AI 에이전트 직원들** (`core/agents.py`): 컨시어지·리졸버 2명·네고시에이터·트래커·
  HITL 코디네이터가 역할별로 배정되어 회사가 조직으로 돌아간다

```bash
python3 -m core demo-list     # 유형별 샘플 이메일 100통
python3 -m core demo-run 1    # 환불 분쟁 1건을 접수→협상→입금 확인까지 단계별 시연
```

**실서비스 모드**: `python3 -m core serve` 가 실제 메일박스(IMAP/SMTP)와 브라우저 실행
(Playwright, 증빙 스크린샷)까지 묶어 데몬으로 돈다 — 맥북 설정 가이드: [`SETUP.md`](SETUP.md)

## 시작하기 (대표용)

맥북에서 Claude Code로 이 저장소를 열고:

1. **고객 요청 처리**: "고객 요청: ○○○" 라고 입력하면 컨시어지 에이전트가 부문에 배분하고 `flows/`에 전 과정을 기록합니다.
2. **신규 기획/개선 지시**: "지시: ○○○" 라고 입력하면 해당 부문 에이전트가 처리하고 결과를 반환합니다.
3. **Flow 확인**: `flows/` 디렉토리에서 모든 업무 흐름을 시간순으로 확인합니다.
