# E2E 테스트케이스 — 유입·온보딩 (ONB)

## TC-ONB-001: 문진 완료 → 첫 위임 후보 1개 선정
- 상태: FAIL
- 우선순위: P0
- 유스케이스: UC-A1
- 워크플로우: workflows/customer-request.md

**Given** 신규 고객이 "고객 요청: 처음인데 뭘 맡기면 좋을지 모르겠어요"로 접수되었다
**When** CS 에이전트가 ops/survey.md의 Q1~Q7 문진을 진행하고 응답을 받으면
**Then** ① `departments/cs/feedback/`에 고객 프로필이 생성되고 ② Q3 기반 첫 위임 후보가 **정확히 1개** 제시되며 ③ Flow 문서에 문진 단계가 기록된다
- 검증: 프로필 파일에 Q1~Q7 응답이 모두 있고, 위임 제안이 1개인지 Flow 문서로 확인

## TC-ONB-002: 문진 중도 이탈 후 이어하기
- 상태: FAIL
- 우선순위: P1
- 유스케이스: UC-A2
- 워크플로우: workflows/customer-request.md

**Given** 고객이 Q4까지 응답하고 세션이 끊겼다
**When** 같은 고객이 재접수되면
**Then** Q1~Q4를 다시 묻지 않고 Q5부터 이어서 진행한다
- 검증: 프로필 파일에 부분 응답이 저장되어 있고, 재개 시 중복 질문이 없는지 대화 로그로 확인

## TC-ONB-003: 위임 금지 목록 존중
- 상태: FAIL
- 우선순위: P0
- 유스케이스: UC-A3

**Given** 고객이 Q4에서 "뉴스레터 읽기는 직접 하고 싶다"고 답했다
**When** 이후 어떤 시점에든 에이전트가 위임 항목을 제안하면
**Then** 뉴스레터 읽기는 제안 목록에 절대 포함되지 않으며, 고객이 직접 위임을 요청해도 "금지 목록에 있다"는 확인을 먼저 거친다
- 검증: 금지 항목이 포함된 프로필로 추천 3회 반복 → 0회 등장 확인

## TC-ONB-004: 일괄 위임 요구 → 한 가지로 축소
- 상태: FAIL
- 우선순위: P0
- 유스케이스: UC-A4

**Given** 신규 고객이 "장보기, 예약, 메일 정리 전부 맡길게요"라고 요청했다
**When** CS 에이전트가 응대하면
**Then** 한 가지(권장 항목 + 이유)부터 시작하도록 안내하고, 나머지는 프로필에 "대기 위임 후보"로 기록한다
- 검증: Flow에 축소 안내가 기록되고, 프로필에 대기 후보 목록이 남는지 확인

## TC-ONB-005: 문진 결과가 추천의 근거로 사용
- 상태: FAIL
- 우선순위: P0
- 유스케이스: UC-A5

**Given** Q6(메마른 감각)=촉각, Q5(희망 활동)=없음 인 고객 프로필이 있다
**When** 상품기획 에이전트가 오프라인 추천을 생성하면
**Then** 추천 사유에 프로필의 Q5/Q6 값이 명시적으로 인용된다 (근거 없는 추천 금지)
- 검증: 추천 문서의 "근거" 항목에 프로필 필드 참조가 있는지 확인

## TC-ONB-006: 온보딩 미완료 상태의 위임 요청
- 상태: FAIL
- 우선순위: P1
- 유스케이스: UC-A6
- 벤치마크: Yohana — 인테이크 품질이 이후 추천 품질을 좌우 (ops/benchmarking.md)

**Given** 문진 미완료(또는 승인 한도 미설정) 고객이 바로 위임을 요청했다
**When** 컨시어지가 접수하면
**Then** 수행에 필요한 최소 항목(해당 위임 관련 문진 + 승인 한도)만 먼저 채우도록 안내하고, 전체 문진을 강요하지 않으며, 미설정 상태로 결제성 위임이 시작되지 않는다
- 검증: 문진 없는 신규 고객의 바로 위임 리허설
