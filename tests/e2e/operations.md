# E2E 테스트케이스 — 대표 운영·큐·과금 (OPS)

## TC-OPS-001: 대표 지시 처리 전 과정
- 상태: FAIL
- 우선순위: P0
- 유스케이스: UC-F1
- 워크플로우: workflows/directive.md

**Given** 대표가 "지시: 문진에 수면 질문 추가 검토"를 입력했다
**When** 컨시어지가 처리하면
**Then** ① 담당 부문(상품기획)이 올바르게 배정되고 ② 산출물이 해당 부문 디렉토리에 저장되며 ③ 결과 반환에 산출물 경로 + Flow 경로 + 맥북 확인 방법 1줄 + 다음 단계 제안 1개가 포함된다
- 검증: 지시 리허설 후 반환 형식 4요소 확인

## TC-OPS-002: Unified Flow View 완전성
- 상태: FAIL
- 우선순위: P0
- 유스케이스: UC-F2

**Given** 고객 요청 1건이 문진→위임→추천→피드백까지 완료되었다
**When** 대표가 해당 Flow 문서 하나만 읽으면
**Then** 어떤 부문이 언제 무엇을 했는지, 핸드오프, 확인 필요 이력, 최종 결과까지 다른 파일을 열지 않아도 파악된다 (단계 누락 0)
- 검증: 완료된 Flow를 제3자 관점으로 읽고 재구성 가능한지 점검

## TC-OPS-003: 슬롯 초과 시 큐 대기·안내
- 상태: FAIL
- 우선순위: P1
- 유스케이스: UC-F3
- 워크플로우: ops/pricing.md

**Given** Unplug One(슬롯 1) 고객의 위임 1건이 진행 중이다
**When** 같은 고객이 두 번째 요청을 보내면
**Then** ① 요청이 큐에 기록되고 ② 대기 순번·예상 시작 시점이 안내되며 ③ 상위 티어 전환 옵션이 강요 없이 1회 안내된다
- 검증: 파일 기반 큐(IT 로드맵 4단계)에서 2건 투입 리허설

## TC-OPS-004: 큐 순서·티어별 슬롯 보장
- 상태: FAIL
- 우선순위: P1
- 유스케이스: UC-F4

**Given** 큐에 요청 3건이 순서대로 쌓여 있고, 고객 티어가 각각 One(1슬롯)/Flow(2슬롯)다
**When** 처리가 진행되면
**Then** 같은 고객 내에서는 접수 순서가 보장되고, Flow 티어 고객은 동시에 2건까지 진행된다
- 검증: 샘플 큐 데이터로 처리 순서 시뮬레이션

## TC-OPS-005: 해지·환불 처리
- 상태: FAIL
- 우선순위: P2
- 유스케이스: UC-F5

**Given** 고객이 월 중 해지와 미사용분 환불을 요청했다
**When** CS가 처리하면
**Then** ① 시점별 환불 규정(수행 전 전액 / 수행 중 부분 / 완료 후 분쟁 절차 — ops/pricing.md에 추가 필요)에 따라 처리되고 ② 이 규정은 요청 접수 시점에 **사전 고지**되어 있었어야 하며 ③ 처리 내역이 Flow에 기록된다
- 검증: 환불 규정 문서 존재 + 사전 고지 노출 + 해지 리허설 (규정이 없으면 규정 작성부터 FAIL)
- 벤치마크: 심부름 앱 분쟁의 핵심 예방책 = 시점별 환불 비율 사전 고지 (ops/benchmarking.md)

## TC-OPS-006: 사용량 한도 사전 통지
- 상태: FAIL
- 우선순위: P2
- 유스케이스: UC-F6

**Given** 고객의 월 위임 시간이 티어 한도의 80%에 도달했다
**When** 다음 위임이 접수되면
**Then** 수행 전에 잔여 한도와 초과 시 선택지(대기/업그레이드)가 안내된다. 차감 기준은 명문화된다 (위임 수행 시간만 차감, 문진·명확화 대화는 미차감)
- 검증: 사용량 샘플 데이터로 리허설

## TC-OPS-007: 장기 대기 타임아웃
- 상태: FAIL
- 우선순위: P1
- 유스케이스: UC-F7
- 벤치마크: 해주세요 — 입찰 미성립 장기 대기가 이탈 원인 (ops/benchmarking.md)

**Given** 큐의 요청이 예상 시작 시점을 넘겨 일정 시간(예: 24시간) 이상 대기 중이다
**When** 타임아웃에 도달하면
**Then** ① 고객에게 지연 사유와 새 예상 시점이 통지되고 ② 고객이 계속 대기/취소를 선택할 수 있으며 ③ 취소 시 사용량이 차감되지 않는다 (방치된 채 조용히 썩는 요청은 0건)
- 검증: 오래된 대기 큐 샘플로 리허설, 통지·선택지·미차감 확인
