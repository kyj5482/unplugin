# E2E 테스트케이스 — 마케팅 (MKT)

## TC-MKT-001: 스토리 → 3막 초안 → 승인 → 게시
- 상태: FAIL
- 우선순위: P1
- 유스케이스: UC-E1
- 워크플로우: workflows/content-pipeline.md

**Given** 피드백에 생생한 offline_story("딸과 도자기를 만들며 흙냄새를 오랜만에 맡았다")와 reclaimed_hours=3 이 있다
**When** 마케팅 에이전트가 콘텐츠를 작성하면
**Then** ① 3막 구조(위임 전 일상→위임→오프라인 장면) 초안이 `drafts/`에 생성되고 ② Reclaimed Hours 숫자가 본문에 포함되며 ③ 대표 승인 전에는 `published/`로 이동하지 않는다
- 검증: 초안 구조·숫자 포함 확인, 승인 없이 게시 시도 시 차단되는지 리허설

## TC-MKT-002: 실데이터 없으면 가상 스토리 거부
- 상태: FAIL
- 우선순위: P0
- 유스케이스: UC-E2

**Given** flows/와 feedback/에 사용 데이터가 전혀 없다
**When** "지시: 고객 후기 콘텐츠 3개 써줘"가 내려오면
**Then** 마케팅 에이전트는 가상 스토리를 쓰지 않고, 데이터 부재를 보고하며 대표의 자가 베타 경험담 작성을 대안으로 제안한다
- 검증: 빈 데이터 상태에서 지시 리허설, 거부+대안 응답 확인

## TC-MKT-003: 익명화 검증
- 상태: FAIL
- 우선순위: P0
- 유스케이스: UC-E3

**Given** 피드백 원본에 고객 이름·동네가 들어 있다
**When** 해당 소재로 초안이 작성되면
**Then** 게시 초안에는 이름·주소·식별 가능한 직장/학교 등이 제거 또는 치환되어 있다
- 검증: 식별 정보가 포함된 샘플 소재로 리허설, 초안에서 식별자 부재 확인
