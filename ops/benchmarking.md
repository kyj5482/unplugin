## 서비스별 교훈

### Yohana — $249/월, 전담 Guide + Specialist 팀
- 온보딩 인테이크 품질이 이후 모든 추천 품질을 좌우. 온보딩 미완료 상태의 위임 요청 처리가 필요 (→ TC-ONB-006)
- "절약한 시간"을 고객에게 보여주는 것 자체가 상품 — 집계 정확성이 테스트 대상
- 1인 전담 → 수요 초과로 팀제 전환: 용량 설계는 처음부터 큐·팀 전제로 (우리의 큐 모델과 일치)
- ⚠️ 현재 도메인 접속 불가 — 소비자 컨시어지의 수익성 리스크 반증 사례로도 참고

### Magic / Fancy Hands — 인간 VA, 크레딧 모델
- Fancy Hands: "1요청 = 최대 20분" 단위 정의, 크레딧 이월. **요청 단위의 범위·초과 과금 규칙을 명문화해야 분쟁이 없다** (→ ops/pricing.md 보완 과제)
- Magic: 민감정보는 일반 채팅과 분리된 "Vault" 경로로만 — 채팅에 카드번호 입력 시 차단·안내 (→ TC-DEL-006 확장)

### 김집사 / 해주세요 — 한국 하이퍼로컬 심부름
- 김집사: 집사가 선결제 후 **영수증 사진 전송** — 대행 결제의 증빙이 신뢰의 핵심 (→ TC-DEL-010)
- 해주세요: 입찰 미성립 시 장기 대기 발생 — 타임아웃·통지·자동취소 필요 (→ TC-OPS-007)
- 업계 공통: 취소 시점별 환불 비율의 **사전 고지**가 분쟁 예방 핵심 (→ TC-OPS-005)

### OpenAI ChatGPT agent (구 Operator) / Anthropic computer use — AI 브라우저 에이전트
Unplugin IT 실행 계층의 직접 선례. 표준 안전 패턴:
- **중대 액션(주문·발송) 직전 사용자 승인** / **Takeover 모드**(로그인·카드 입력은 사용자가 직접, 그동안 기록 중지) / **Watch 모드**(민감 사이트는 감독 하에만)
- CAPTCHA는 자동 해결 금지(사용자 핸드오버), 고위험 거래(은행 이체)는 자체 거부 목록
- 검증된 실패 모드: 복잡 UI 조작 실패, **성공 미검증 상태의 "완료" 보고(허위 완료)**, **프롬프트 인젝션**(대상 페이지에 심긴 악성 지시), Takeover 후 재개 실패
- 한도 차감 규칙 선례: 사용자 지시만 차감, 명확화 응답은 미차감 (→ ops/pricing.md 참고)

### Opal / one sec — 디지털 디톡스
- 측정은 행동 지표로: one sec은 "앱 실행 시도 57% 감소"(피어리뷰 연구), Opal은 스크린타임 기반 절약 시간. **Reclaimed Hours도 자가보고 + 스크린타임 델타 이중 측정** (→ TC-OFF-004)
- 개입 로직 온디바이스 처리(프라이버시)가 차별화 — 스크린타임 권한 거부 시 폴백 필요

### Meta "Muze" — 2026-11-04 정정: 실재 확인, 피벗의 직접 계기
2026-11-02 웹 조사에서는 실재 근거를 찾지 못했으나, **대표가 직접 사용해
확인함** (2026-11-04). 개인 비서형 대행 업무(이메일 연결 포함)를 대부분 수행.
→ 우리는 Muze와 대행으로 경쟁하지 않고, Muze **위에서** 절약 시간·감정을
자동 측정해 오프라인 무브먼트로 전환시키는 레이어로 피벗 (`ops/pivot-2026-11-04.md`).
Muze 완료 알림 메일의 실제 포맷 확보가 측정 v0의 첫 과제.

OpenAI "Dots"는 여전히 실재 근거 없음 — 벤치마킹 제외 유지.

## 체크리스트 반영 현황

리서치 체크리스트 22항목 중 TC 반영 20항목. 보류 2건:
- 멀티채널 접수 dedupe → 채널이 1개(Claude Code)인 현 단계에서 불필요, 채널 확장 시 TC 추가
