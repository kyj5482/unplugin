# KPI 설계 — Reclaimed Hours (북극성 지표)

> 2026-11-04 피벗(`ops/pivot-2026-11-04.md`)으로 깔때기 앞단이 바뀌었다:
> 우리가 위임받아 수행한 시간(Delegated)이 아니라, **외부 에이전트(Muze 등)가
> 벌어준 시간을 자동 측정한 값(Saved)**이 입구다.

## 정의

**Reclaimed Hours** = AI 에이전트가 벌어준 시간 중, **실제 오프라인 무브먼트
(관계·배움·오감)로 전환된** 시간.

단순히 "에이전트가 대신 한 시간"이 아니다. 전환 깔때기로 측정한다:

```
① Saved Hours      : 에이전트가 벌어준 시간 — 완료 알림 자동 파싱 ×
                     업무 유형별 baseline_minutes. 수동 입력 금지.
   + Emotion Saved : 회피한 감정 부하 — 유형별 emotion_load(1~5) × 회피 횟수.
                     환불·분쟁 등 스트레스 유형은 시간보다 이 값이 크다.
        │   × 전환율
        ▼
② Reclaimed Hours  : 그 시간 중 실제 오프라인 무브먼트에 쓰인 시간
                     (CS 피드백 offline_realized/reclaimed_hours + 스크린타임 델타 교차)
        │   × 깊이
        ▼
③ Growth           : 무브먼트의 질 — 관계가 생겼나, 배움이 이어지나, 오감을
                     느꼈나 (offline_story 정성 평가, 추후 점수화)
```

Task 단위 표시 원칙: 요청 1건마다 "절약 시간 N분 · 아낀 감정 M"이 자동으로
붙고, 누적은 **시간 배당 잔고**로 보여준다. 잔고가 임계치에 닿으면 넥스트
무브먼트 제안이 나간다 — 측정은 그 자체가 목적이 아니라 다음 움직임의 트리거다.

## 부문별 기여 지표

| 부문 | 움직이는 지표 | 어떻게 |
|---|---|---|
| IT | ① 포착률 | 완료 알림 파싱 커버리지(지원 에이전트·업무 유형 확대), baseline 테이블 정확도 |
| CS | ①→② 전환율 | 팁 실행 가이드, 무브먼트 제안 응답률, 피드백 실측 |
| 상품기획 | ②, ③ | 잔고·취향에 맞는 무브먼트(관계·배움·오감) 추천 적중률 |
| 마케팅 | 신규 ① | "내가 아낀 시간과 감정" 숫자가 담긴 스토리로 신규 유입 |

## 측정 소스 (현 단계: 파일 기반)

- 에이전트 완료 알림 메일 → `core/mail_io.py` 수신 → `core/classify.py` 유형 매칭
  → `core/plugins/` 카탈로그의 `baseline_minutes`/`emotion_load`로 적립 (측정 v0 과제)
- `flows/` — 적립·전환 이벤트 기록
- `departments/cs/feedback/` — `offline_realized`, `reclaimed_hours`, `offline_story`
- 스크린타임 델타 — 자가보고 교차 검증 (TC-OFF-004)

## 안티 지표 (하지 않을 것)

- 체류시간·세션 수 늘리기 — 우리는 디지털 사용을 **줄이는** 회사다
- **수동 기록 요구** — 사용자가 직접 입력해야 쌓이는 지표는 지표가 아니다
- 위임·실행 건수 자체 — 전환 없는 절약은 잔고에 잠든 돈일 뿐이다
